# Ежедневная внешняя копия

VPS формирует архив в 03:30 UTC. Windows-задача `CatsPajamas-OffServerBackup` забирает свежий архив в **08:00 по локальному времени** (Самара, UTC+4), проверяет SHA-256 и только после этого публикует файл. Хранятся 30 дней копий; удаляются только архивы с точным именем `YYYYMMDD-HHMMSS.tar.gz`. Секреты входят в архив: каталог доступен текущему пользователю и SYSTEM, архивы нельзя добавлять в Git.

Установка из корня репозитория, без администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ops\backup-install.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ops\backup-collect.ps1
```

Требуются существующий SSH alias `cats-pajamas`, ключ без интерактивного запроса и уже проверенный ключ сервера в `known_hosts`. Проверка ключа сервера обязательна. Используются SSH/SCP из Git for Windows. На VPS ничего не устанавливается и восстановление БД не запускается.

Проверка расписания и состояния:

```powershell
Get-ScheduledTaskInfo -TaskName CatsPajamas-OffServerBackup
Get-Content C:\Users\bond\mcp\cats-pajamas-backups\status.json
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ops\backup-test.ps1
```

`status.json`: `ok=true`, время проверки UTC, имя архива и SHA-256. При ошибке задача возвращает 1, записывает `ok=false` и пытается показать неблокирующее уведомление Windows не чаще одного раза за 24 часа (если уведомления недоступны, дополнительных окон нет). Следующий запуск задачи повторяет попытку автоматически. Три попытки с интервалом 10 секунд, SSH connect timeout 30 секунд; Task Scheduler ограничивает весь запуск 20 минутами. Архив старше 36 часов считается ошибкой. Проверки не обращаются к серверу, используют временные фикстуры.

**Ограничение:** задача выполняется только при входе пользователя в Windows и включённом компьютере. `StartWhenAvailable` подхватывает пропущенный запуск; выключенная машина не создаёт внешних копий. При длительном отсутствии нужно проверять `status.json` после входа. Это внешняя копия на компьютере владельца, не постоянно работающая резервная инфраструктура. Путь скриптов должен оставаться доступным; при переносе репозитория повторить установку. При изменении часового пояса скорректировать время задачи.

## Подготовленный канал GitHub Actions — пока отключён

`backup.yml` запускается в 04:15 UTC (08:15 Самара), но выполняет работу **только** при repository variable `CATS_BACKUP_ENABLED=true`. Сейчас установка на VPS и новый постоянный секрет не выполнены. Расписание GitHub может задерживаться; ошибки видны в результате workflow. Артефакты зашифрованы и запрашивают хранение 30 дней в пределах политики репозитория. Это резервные копии, а не автоматический деплой.

Для включения требуется отдельное разрешение владельца на установку ограниченного пользователя VPS и сохранение **нового backup-only** SSH private key в `CATS_BACKUP_SSH_KEY`. Общий root/release ключ для этого не подходит. RSA recovery private key остаётся только у владельца; публичный `backup-recipient.pem` копируется на сервер.

При недоступном локальном SSH подготовлен ручной `backup-bootstrap.yml`. Он допускает только main с успешным Check для точного commit, принимает новый Ed25519 public key как текстовый input, доставляет проверенные исходники во временный каталог VPS и запускает установщик плюс начальную публикацию. Входящий public key передаётся через environment, проверяется до SSH; Private backup key этот workflow не создаёт: получает новый `CATS_BACKUP_SSH_KEY` из secrets и до любых изменений VPS проверяет совпадение его публичной части с согласованным input без вывода значений. Временная файловая копия удаляется при любом исходе. Для этого отдельного, заранее разрешённого запуска нужен временный `CATS_RELEASE_SSH_KEY` с root-доступом; его удаление из repository secrets после согласованных разовых операций выполняется владельцем/агентом отдельно. Workflow удаляет свою временную файловую копию ключа при любом исходе. Bootstrap не включает расписание и не выполняет deployment приложения. После установки workflow новым ограниченным ключом скачивает один свежий encrypted envelope и проверяет реальный отказ id/bash/SCP-команды, SFTP subsystem, PTY и remote forwarding. Отказ команды засчитывается только при точном ответе forced-command и exit 1; network/auth/timeout ошибки не засчитываются. Неуспешные проверки доступа оставляют расписание отключённым; уже завершённая транзакция установки при этом сохраняется для диагностики. Если установка, начальная публикация, проверка sshd или reload неуспешны, установщик откатывает только созданные им точные файлы, новые пустые каталоги и нового пользователя/группу; восстанавливает конфигурацию сервисов без удаления прежних файлов. Расписание остаётся отключённым. Уже существующая конфигурация отклоняется до изменений.

После разрешения администратор передаёт установщику файл с одним новым Ed25519 **публичным** ключом:

```sh
sudo bash ops/backup-channel-install.sh /absolute/path/new-backup-key.pub
```

Установщик требует существующий root backup-service, `/usr/bin/node`, gzip и GNU tar, поддержку sshd drop-in Include. Он отказывается изменять уже существующего `cats-backup`, группу или свои каталоги/конфиги. При несовпадении предпосылок нужна проверка фактической конфигурации VPS, а не обход отказа. Скрипт не генерирует ключи и не обращается к GitHub. Исходный backup-service сохраняется: добавляется только `ExecStartPost`, который после успешного backup публикует encrypted envelope. Начальная публикация свежего существующего архива выполняется внутри транзакции установщика до успешного reload; backup-service во время установки не запускается. Файлы модуля и публичный ключ устанавливаются root в `/usr/local/lib/cats-backup`, вне изменяемого каталога проекта.

Пользователь `cats-backup` читает только root-owned `/var/lib/cats-backup-export/latest.enc`. Forced command принимает ровно `export-latest`; shell, SCP/SFTP, PTY и forwarding запрещены. Исходные архивы с секретами ему не выдаются. Имя, возраст до 36 часов, размер до 512 MiB, отсутствие symlink, целостность gzip/tar и SHA-256 проверяются перед шифрованием. Неуспешная публикация сохраняет предыдущий envelope, который перестаёт экспортироваться после истечения свежести. На GitHub проверяются формат/свежесть и границы размера; криптографическая проверка AES-GCM выполняется при локальном расшифровании существующим `backup-envelope.mjs`.

До включения `CATS_BACKUP_ENABLED` обязательна проверка новым ограниченным ключом: `export-latest` выдаёт envelope; `id`, `bash`, SCP/SFTP и PTY/forwarding отвергаются. Затем ручной workflow должен скачать только `.enc`, который локально расшифровывается с совпадением SHA-256. После этого проверяется первый успешный ежедневный запуск. Настройка расписания сама по себе не подтверждает работоспособность.

Локальные проверки, без серверов и постоянных ключей:

```sh
node ops/backup-channel-test.mjs
node ops/backup-installer-test.mjs
bash -n ops/backup-channel-install.sh ops/backup-export.sh
```

Тест использует одноразовый RSA fixture во временной папке: проверяет roundtrip, отказы команд, свежесть, повреждённый gzip и сохранение предыдущей копии. Symlink fixtures выполняются на POSIX; Windows пропускает их из-за ограничений создания symlink. На Windows тест добавляет gzip/GNU tar из Git for Windows только в собственный PATH. Installer fixtures запускаются в изолированных временных каталогах с подставными административными командами и проверяют откат при отказах sshd, эффективной политики, публикации и reload; реальные системные файлы и пользователи не меняются. Реальные права SSH/systemd подтверждаются только при отдельно разрешённой установке. Отключение канала: установить `CATS_BACKUP_ENABLED=false`; удаление пользователя/ключа на VPS требует отдельной явной операции администратора.

### Получение копии из GitHub на Windows

После установки и успешной проверки канала можно заменить существующую задачу командой `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ops\backup-github-install.ps1`. До разрешённой активации её не запускают. Имя задачи остаётся `CatsPajamas-OffServerBackup`, время меняется на 08:45 по Самаре — после запуска GitHub в 08:15. Задача работает от текущего пользователя без повышения прав и подхватывает пропущенный запуск после входа.

`backup-github-collect.ps1` получает только артефакт успешного scheduled/manual запуска `backup.yml` на `main`. Скачивание ZIP ограничено размером и временем; распаковка принимает единственный обычный файл `latest.enc`, проверяет заявленный и фактически прочитанный размер. Архив должен быть свежим. Расшифрование выполняется только на компьютере владельца, затем независимо сверяется SHA-256. Неверные копии не заменяют ранее проверенные архивы. Общая блокировка исключает одновременную запись со старым SCP-коллектором; сообщения об ошибках остаются неблокирующими и ограничены одним уведомлением в сутки.

Локальные фикстуры запускаются через Windows PowerShell 5.1: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\ops\backup-github-test.ps1`. Они используют временный тестовый ключ и подставной GitHub-процесс; реальные копии, ключи и планировщик не затрагиваются. Успешный ручной запуск не заменяет доказательство следующего фактического ежедневного запуска.
